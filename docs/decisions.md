## 구현 중 정한 세부 사항 (요구서 범위 안의 해석)

- **추가 테이블:** `conversations`(대화 단위 누적 조건), `chat_messages`(최근 대화 이어보기). 요구서에 `conversation_id`만 있고 저장 테이블이 없어서 추가.
- **추가 컬럼:** `users.avoid_subcategories`(온보딩 '피하는 아이템', 결정 13 이후 미사용), `users.region_code`, `users.avatar_url`, `outfits.rank`·`label`·`favorited_at`, `agent_runs.source`·`is_free_tier`, `outfit_items.user_id`(RLS용).
- **feedback_type `reroll`:** '다시 짜기' 기록. 개인 선호도의 "최근 다시 짜기 조합 감점"에 사용.
- **API 데이터 접근:** 서버는 PostgREST를 **사용자 본인 JWT로** 호출해 RLS가 항상 적용되게 함. 서비스 키는 날씨 캐시·계정 삭제·AI 키 저장에만 사용.
- **태그 코드:** DB에는 영문 코드(예: `knit`, `ivory`), 화면에는 한글. 전체 목록은 `api/app/domain/taxonomy.json`.
- **색 계열(톤온톤 판단):** mono(블랙·화이트·그레이·차콜), warm_neutral(아이보리·베이지·브라운), blue(네이비·데님 블루·블루·스카이블루), green(그린·카키), red(레드·핑크), purple, yellow(옐로·오렌지).
- **핏 사진 → 실루엣:** 핏 사진은 옷 한 벌 전체를 보여 주므로, 고른 상의 핏에 맞는 하의 실루엣도 함께 저장한다 (슬림→슬림, 레귤러→스트레이트, 세미오버→스트레이트·와이드, 오버→와이드).
- **상황(occasion) 표준값:** 소개팅, 데이트, 출근, 회의, 면접, 학교, 친구 모임, 가족 모임, 결혼식, 여행, 운동, 쇼핑, 일상. 그 외는 사용자 표현 그대로.
- **옷 묶음(그룹):** "바지"(슬랙스·데님·면바지·조거·반바지), "치마", "원피스", "아우터", "티셔츠"는 여러 세부 종류를 한 번에 가리키는 묶음으로 처리한다 (`taxonomy.json`의 `groups`, 피드백 `exclude_group`). AI가 놓친 분명한 제외 표현("바지 빼줘", "치마 말고")은 코드 규칙이 보완하고, 무엇을 뺄지 모르면 다시 짜지 않고 되묻는다. AI가 응답하지 않을 때도 규칙으로 알아들을 수 있는 요청은 처리한다. 인식 평가: `eval/run.py --llm live --parse` (표현 30개, 수정 전 70% → 수정 후 93–97%).
- **규칙 보완:** AI가 재시도 2회 후에도 코디 3개를 못 만들거나 AI 호출이 실패하면, 코드가 후보 옷으로 검증을 통과하는 조합을 만들어 점수순으로 채운다. 평가에서는 "LLM만으로 성공"과 "규칙 보완 포함"을 따로 센다.
- **계절 경계:** 아이템 계절이 대상 날짜 계절과 달라도, 기온이 맞으면 허용한다 (8° 이하 → 겨울옷, 23° 이상 → 여름옷, 12–22° → 봄·가을옷). 늦가을 한파·초가을 더위 대응.
- **Claude(내 키) 거절 대비:** Claude Sonnet 5.5 호출에는 Anthropic 서버 측 fallback(`fallbacks: "default"`)을 켜 둔다. 안전 분류기가 거절하면 같은 호출 안에서 다른 모델이 이어 받는다.
